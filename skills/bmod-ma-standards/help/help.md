# ma-standards knowledge

This document covers the skills of the `ma-standards` module: what each one gives the user and when to recommend it.

The module is the organisation's engineering standards as skills: language standards (C++, C#, Python, JavaScript/TypeScript, React, CMake), quality standards (logging, telemetry, documentation, review, tests), the git workflow, and session conventions (audit trail, revision history, bug detection). A standard applies to the work its line names: recommend it before that work starts, not after. `ma-standards-apply` writes the same list into the project's instruction files so every agent session sees it without asking.

## Skills

- `cpp-best-practices`: Baseline C++ coding standards: naming, code organization, memory, error handling, modern C++17/20/23 idioms and build flags. Recommend it when writing, reviewing or refactoring C++ code or setting up a C++ project.
- `cpp-concurrency-safety`: Safe C++ multi-threading: RAII locking, task-based parallelism, minimal shared mutable state, condition variables instead of sleeps. Recommend it when working with C++ threads, mutexes, futures or asynchronous operations.
- `cpp-const-correctness`: Immutable-by-default C++: const variables and member functions, constexpr where possible, consistent parameter-passing rules. Recommend it when declaring C++ variables, defining member functions or moving logic to compile time.
- `cpp-memory-handling`: Memory-safe C++: smart pointers, no raw new/delete, RAII for every resource, standard containers, Rule of Zero/Five. Recommend it when writing memory-intensive C++ code, implementing classes, or debugging leaks and dangling pointers.
- `cpp-modern-composition`: Modern C++ composition: STL algorithms over manual loops, named casts, brace initialization, no raw memory manipulation. Recommend it when writing C++ algorithms, refactoring C-style code or transforming collections.
- `cpp-robust-interfaces`: Contract-based C++ interfaces: explicit pre- and post-conditions, strong types, ownership-free raw pointers, spans and string_view. Recommend it when designing C++ headers, function signatures or public APIs.
- `csharp-best-practices`: Modern C# (10-12) coding standards: naming, nullable reference types, async/await, LINQ, error handling, DI lifetimes and testing. Recommend it when writing, reviewing or refactoring C# code or setting up a .NET project.
- `python-best-practices`: Modern Python (3.10+) coding standards: PEP 8 naming, type hints, match/case, exception groups, async patterns and packaging with uv. Recommend it when writing, reviewing or refactoring Python code or setting up a Python project.
- `python-dependency-mgmt`: Reproducible Python dependencies with uv lockfiles or layered, pinned requirements files, in a project-local virtual environment. Recommend it when managing Python dependencies, pyproject.toml, uv.lock or requirements.txt.
- `python-security-skill`: Secure Python aligned with OWASP Top 10 2025: no eval/pickle on untrusted data, parameterized queries, modern hashing, locked dependencies, safe error handling. Recommend it when writing or reviewing Python that handles input, secrets, data or dependencies.
- `js-ts-dependency-mgmt`: JavaScript and TypeScript dependency hygiene across npm, Yarn and pnpm: lockfiles, exact pinning, audits, dependency categories and .npmrc. Recommend it when editing package.json, lockfiles or .npmrc, adding packages, or auditing the JS supply chain.
- `js-ts-security-skill`: OWASP Top 10 2025 security checks for JavaScript and TypeScript, with a scan script covering lockfiles, dependency audits, dangerous patterns, empty catch blocks and hard-coded secrets. Recommend it when reviewing security-critical JS/TS code, adding dependencies, or running a security audit.
- `vercel-react-best-practices`: Vercel's 57 React and Next.js performance rules in 8 priority-ordered categories: waterfalls, bundle size, server-side, client data fetching, re-renders, rendering, JavaScript and advanced patterns. Recommend it when writing, reviewing or optimizing React or Next.js code.
- `cmake-best-practices`: Modern target-based CMake (3.0+): target_* commands, PUBLIC/PRIVATE/INTERFACE scopes, compile features instead of flags, namespaced alias targets. Recommend it when creating or modifying CMakeLists.txt or any C++ build configuration.
- `logging-best-practices`: Structured, context-rich logging with mandatory fields and a full-stack-trace exception policy for backend, frontend, realtime and algorithmic code. Recommend it when adding or changing log statements, error handling or new service classes.
- `opentelemetry-best-practices`: OpenTelemetry tracing and metrics: semantic conventions, context propagation across async boundaries, span granularity, meaningful counters and histograms. Recommend it when instrumenting endpoints or distributed requests, or adding monitoring and metrics.
- `code-documentation`: Standard file headers and method documentation for C++, C#, JavaScript, TypeScript and Python (Doxygen, XML docs, JSDoc, docstrings). Recommend it when creating or modifying source files, functions, methods or public APIs.
- `code-review`: Comprehensive code review covering quality, best practices, security, testing and documentation, with defects in already-delivered code reported separately from review findings. Recommend it when the user asks for a code review or to review a change, diff or pull request.
- `test-generator`: Generates unit and integration tests covering happy paths, edge cases, error cases and integrations in the Arrange-Act-Assert pattern. Recommend it when the user asks to generate tests for code, or new logic needs test coverage.
- `test-accompanied-development`: Every new public method or function is accompanied by at least one unit test written in the same change. Recommend it when adding public methods, functions or APIs.
- `git-workflow-skill`: Worktree-based git workflow: an isolated feature branch per change, Conventional Commits, PR-only integration and hook installation, with scripted start, finish and validate. Recommend it when any change to tracked files is about to start, when committing, or when opening a pull request.
- `commit-message`: Writes Conventional Commits messages (type, scope, subject, body, footer) from the code changes at hand. Recommend it when the user asks for a commit message or is about to commit.
- `auto-bug-detection`: Identifies defects in already-delivered code during any session, classifies code as delivered or in progress through the ticket store, and files confirmed defects through bmad-agent-po. Recommend it when reading or reviewing code that a finished ticket delivered.
- `ai-audit-trail`: Appends a per-session entry (date, task, estimated tokens) to the project's AiAudit.md. Recommend it when a significant agent session or multi-step workflow ends.
- `document-revision-history`: Maintains a revision history table at the top of generated and updated documents, one consolidated row per version. Recommend it when generating or updating planning, specification or design documents.
- `skill-creator`: Guide for creating effective skills: structure, concise content, progressive disclosure, bundled scripts, references and assets, with init, validate and package scripts. Recommend it when the user asks to create, structure, validate or package a skill.
- `project-context-expansion`: Post-retrospective capture of conventions and patterns into the project's Project-Specific Rules, proposed by the agent and approved by the user. Recommend it when a retrospective has just ended, or the user says 'expand project context'.
- `open-presentation`: Opens the BMAD-METHOD AI Development Training deck shipped with this skill in the system's presentation viewer. Recommend it when the user asks to open the methodology presentation or the training slides.
- `ma-standards-apply`: Writes or removes the ma-standards block in the project's instruction files (AGENTS.md, CLAUDE.md, .clinerules, .roomodes, .github/copilot-instructions.md). Recommend it when the user says 'apply the standards' or 'remove the standards block'.
